# 学习中心 UI 优化提案（2026-07-15）

> 状态：Draft，供评审
>
> 范围：Renderer 页面布局、视觉层级和交互入口；不修改学习数据模型、IPC 契约或主进程能力。

## 一、提案结论

学习中心保留“笔记、Skill、浏览器 AI 任务”三类能力，但把它们整理成统一的学习工作台：

- 顶部只负责页面导航、视图切换和当前视图的主操作。
- 笔记视图以编辑区为视觉中心，左侧负责定位内容，右侧只承载轻量元信息。
- 分类管理从常驻面板改为按需打开，减少左侧栏的垂直占用。
- 保存状态、编辑模式和当前笔记标题集中到编辑区顶部，避免用户在多个区域寻找状态。
- 浏览器 AI 入口改成清晰的主操作，历史任务作为独立视图，不与新建笔记、Skill 操作混在一起。
- 深浅色主题继续复用现有 token、`surface-card`、`quiet-control` 和 `app-chrome`，不新增一套颜色体系。

目标不是增加更多模块，而是让用户打开学习中心后能快速完成三件事：找到一条笔记、持续编辑内容、确认内容已经保存。

## 二、当前实现基线

当前页面已经具备较好的功能拆分，主要结构如下：

```text
LearningCenterPage
├─ LearningCenterHeader
├─ notes
│  ├─ LearningNotesSidebar
│  ├─ LearningEditorPanel
│  └─ LearningNoteInfoSidebar
├─ skills
│  └─ SkillManagementView
└─ browser-tasks
   └─ LearningBrowserAiHistoryView
```

笔记视图当前采用三栏布局：左侧 `280px`，中间自适应，右侧 `340px`。左右侧栏支持折叠，编辑区支持分栏和纯预览模式，笔记和分类的 CRUD、Markdown 编辑快捷键、保存和浏览器 AI 调度均已存在。

这意味着本次优化可以停留在 renderer 页面域内，主要落点是：

- `src/core/renderer/pages/LearningCenterPage.tsx`：继续只负责状态和区域装配，必要时减少布局判断。
- `src/core/renderer/pages/learning/layout/`：统一顶部工作台导航。
- `src/core/renderer/pages/learning/notes/`：优化列表、编辑区和信息侧栏。
- `src/core/renderer/pages/learning/skills/`：与笔记视图对齐布局和操作层级。
- `src/core/renderer/styles/`：只补充学习中心需要的页面级样式 token 或布局类。
- `src/core/renderer/i18n/messages/learning.ts`：补充所有新增用户可见文案。

## 三、现有体验问题

### 1. 顶部操作层级偏满

当前顶部同时放置视图切换、新建、浏览器 AI、历史任务和偏好入口。笔记、Skill、浏览器任务的主操作不同，但按钮在同一层级，用户需要先理解页面状态才能判断哪个按钮会改变什么。

### 2. 左侧栏混合了三种任务

搜索、分类筛选、分类新建/重命名/删除和笔记列表集中在一个常驻面板里。分类管理控件在大多数时间并不需要，却会持续占用列表前的空间，导致真正用于浏览笔记的区域变短。

### 3. 编辑区的核心信息不够集中

当前编辑区顶部显示笔记标题、编辑模式和保存按钮，但标题不能直接编辑，分类、标签和状态又分散在右侧或弹窗中。用户在编辑内容时需要跨区域确认“当前编辑的是谁”和“这次修改是否已保存”。

### 4. 面板边界较多，内容焦点被削弱

三栏外层、每个面板、面板内部标题区和编辑器本身都使用边框或圆角表面。视觉上容易形成多个并列卡片，编辑区没有足够强的主舞台感。

### 5. 空态和窄窗口策略需要更明确

左右侧栏折叠已经支持，但窄窗口下仍然需要在三栏之间切换。顶部视图切换在较小宽度会隐藏，用户需要依赖其他入口才能访问 Skill 或历史任务，响应式行为不够连续。

## 四、目标信息架构

```text
学习中心
├─ 工作区导航
│  ├─ 笔记
│  ├─ Skills
│  └─ AI 任务
├─ 当前视图工具栏
│  ├─ 当前内容定位
│  ├─ 视图/筛选控制
│  └─ 当前视图主操作
└─ 工作内容区
   ├─ 内容导航栏（可折叠）
   ├─ 编辑 / 预览主区域
   └─ 元信息栏（可折叠）
```

导航层只表达“我在哪里”，工具栏只表达“我现在能做什么”，内容区只表达“我正在处理什么”。三层不重复承担相同的信息。

## 五、目标布局

### 1. 页面级布局

```text
┌──────────────────────────────────────────────────────────────────────┐
│ ← 学习中心                         笔记 | Skills | AI 任务     主操作 │
├──────────────────────────────────────────────────────────────────────┤
│ 当前视图工具栏：路径 / 当前标题        搜索、视图、更多操作           │
├───────────────┬──────────────────────────────────┬───────────────────┤
│ 内容导航       │ 编辑工作区                         │ 信息栏            │
│ 搜索           │ 标题 + 保存状态 + 编辑模式          │ 分类              │
│ 分类筛选       │ Markdown 编辑 / 实时预览            │ 标签              │
│ 笔记列表       │                                    │ 状态与日期         │
│               │                                    │ 更多操作           │
└───────────────┴──────────────────────────────────┴───────────────────┘
```

推荐尺寸：

- 页面外层继续使用现有最大宽度和留白。
- 左侧内容导航 `248px - 288px`，不再固定为更宽的管理面板。
- 右侧信息栏 `264px - 300px`，只展示摘要信息。
- 中间编辑工作区保持 `minmax(0, 1fr)`，保证 Markdown 内容获得最大连续宽度。
- 当两侧均折叠时，中间区域继续居中，但不额外套一层卡片。

### 2. 顶部工作区导航

保留返回按钮、学习中心标题和三种视图，但调整为两层：

- 第一层：页面身份、三段式视图切换、当前视图主操作。
- 第二层：仅在笔记视图显示当前分类/笔记定位、编辑模式、更多操作。

建议的主操作：

| 视图 | 主操作 | 次操作 |
| --- | --- | --- |
| 笔记 | 新建笔记 | 浏览器 AI、历史任务、更多 |
| Skills | 新建 Skill | 更多 |
| AI 任务 | 新建 AI 任务 | 清理/筛选历史、更多 |

浏览器 AI 偏好设置不再依赖右键触发。它应放入浏览器 AI 按钮旁的更多菜单或设置入口，并提供明确的图标、标题和 tooltip。

### 3. 笔记左侧导航

左侧栏只保留“查找和选择内容”：

1. 顶部搜索框，支持清空和快捷聚焦。
2. 一行紧凑筛选：全部、当前分类、未整理/草稿等状态筛选。
3. 笔记列表，保留标题、摘要、更新时间和状态。
4. 底部或标题旁的分类管理入口，打开轻量弹层或对话框。

分类管理面板不再默认展开。只有点击“管理分类”后才展示新建、重命名和删除，关闭后恢复完整笔记列表高度。

列表项建议保持三种视觉信息：

- 标题作为主文本，单行截断。
- 摘要作为弱化信息，最多两行。
- 更新时间和状态作为底部元信息，避免与标签堆叠。

当前笔记使用细边框和浅色背景表达选中状态，继续保留，但把主色限制在选中指示和键盘焦点，不让整个列表变成大面积蓝色。

### 4. 中间编辑工作区

中间区域是页面的主舞台，建议调整为：

- 顶部固定工具栏：当前笔记标题、未保存提示、保存按钮。
- 标题可在编辑区顶部直接编辑，分类/标签/状态通过“编辑信息”打开，不阻塞 Markdown 编辑。
- 编辑模式控件统一为三段式：编辑、分栏、预览。当前实现的分栏/纯预览保留，新增纯编辑作为高频写作模式。
- 编辑器和预览使用同一块连续表面，减少内部重复标题栏和嵌套边框。
- 保存按钮只在有修改时突出；无修改时显示轻量的“已保存”状态，不抢占注意力。
- 当没有选中笔记时，空态直接提供“新建笔记”和“选择已有笔记”两个动作，而不是只有一段说明文字。

编辑器需要保留现有能力：Markdown 右键插入、列表续写、缩进、撤销/重做、快捷键保存和主题适配。

### 5. 右侧信息栏

右侧栏从“完整管理面板”收敛为“当前笔记摘要”：

- 标题和当前状态。
- 分类和标签。
- 创建/更新时间。
- 保存状态和错误提示。
- 编辑信息作为主要次操作。
- 删除放进更多操作或底部危险操作区，降低误触概率。

信息栏不重复渲染可以直接在编辑器顶部确认的内容。它的价值是让用户在编辑时随时看到上下文，而不是替代编辑表单。

## 六、其他视图

### Skills

Skill 视图沿用笔记的工作台骨架，但内容区域改为 Skill 列表和编辑表单：

- 左侧列表提供搜索、分类筛选和启用状态。
- 中间编辑区突出 Skill 标题、正文和启用开关。
- 删除使用危险操作区，不与保存按钮并排抢注意力。
- 分类管理与笔记使用相同的按需弹层模式。

笔记和 Skill 不强行共用业务组件，但应共享布局间距、列表选中态、搜索框、空态和操作按钮层级。

### AI 任务

AI 任务视图从“历史记录列表 + 详情”明确为任务时间线：

- 顶部显示筛选条件和“新建任务”。
- 列表项显示任务问题摘要、目标站点、来源数量、状态和时间。
- 详情区优先展示回答，其次展示来源和执行步骤。
- 失败、取消、等待登录和成功使用稳定的状态颜色与文字，不依赖颜色单独传达状态。
- 重新打开任务时保留原有上下文选择，但不自动覆盖当前笔记。

## 七、响应式和可访问性

### 窗口宽度策略

| 宽度 | 布局 | 行为 |
| --- | --- | --- |
| `>= 1280px` | 三栏工作台 | 左右栏可手动折叠 |
| `900px - 1279px` | 左栏 + 编辑区，右栏默认收起 | 信息栏通过 rail 或抽屉打开 |
| `< 900px` | 单栏 | 内容导航、编辑区、信息栏作为可切换面板 |

视图切换不能只依赖 `hidden` 让按钮消失。窄窗口需要保留一个可访问的菜单或底部/顶部 segmented control，确保 Notes、Skills、AI 任务始终可达。

### 交互要求

- 现有 `Ctrl/Cmd + S`、左右侧栏快捷键和鼠标手势继续保留。
- 所有只显示图标的按钮补充 tooltip 和 aria-label。
- 删除、清理历史等不可逆操作保持二次确认。
- 搜索无结果、没有笔记、没有 Skill、AI 任务为空和加载失败分别提供可执行的空态。
- 键盘焦点在侧栏折叠、视图切换、保存失败重试后保持可预测。

## 八、视觉方向

参考当前项目的 Apple-like 视觉体系以及给定的 Markdown 工作台示例，采用“轻边界、内容优先、低对比”的方向：

- 页面背景、工作区背景和编辑器背景只做轻微层级区分。
- 工作台外层不再使用过重的卡片包裹，面板之间用细边框和留白建立关系。
- 圆角统一在现有体系内收敛，避免每个控件使用不同半径。
- 蓝色仅用于主操作、选中态、焦点态和链接，不作为大面积背景。
- 状态颜色沿用现有 success/destructive/muted token，并确保深浅主题均有足够对比度。
- Markdown 正文继续使用现有预览样式，编辑器使用等宽字体；不要为了“像文档”把整个应用改成纯白纸张风格。

## 九、实施边界与顺序

### P0：布局和层级调整

- 重排 `LearningCenterHeader`，拆分页面导航和笔记工具栏。
- 调整笔记三栏尺寸、边界和编辑区顶部状态。
- 分类管理改为按需打开。
- 增加笔记无选中时的可执行空态。
- 保留所有现有数据和 IPC 调用。

### P1：统一视图体验

- 对齐 Skills 的列表、编辑器和危险操作层级。
- 重做 AI 任务视图的列表/详情信息层级。
- 补齐窄窗口下的视图切换和侧栏抽屉。

### P2：细节和验证

- 补齐中英文 i18n 文案。
- 检查深浅色主题、键盘导航、tooltip、空态和错误态。
- 用真实窗口尺寸验证三栏、双栏、单栏和两侧折叠状态。
- 为新提取的纯函数或状态转换补充测试；纯视觉调整不扩大测试范围。

明确不在本次 UI 提案中处理：

- 学习笔记存储格式和目录结构。
- Browser AI 的 Edge/CDP 启动、登录态和站点适配器。
- 新增全局 store、IPC 或主进程 domain。
- Markdown 渲染器能力扩展。

## 十、验收标准

- 用户进入学习中心后，三秒内可以识别当前视图和主操作。
- 笔记列表中，搜索框、分类筛选和笔记列表在常规窗口高度内同时可见。
- 编辑区在三栏布局下拥有最大连续宽度，标题、编辑模式、保存状态集中在顶部。
- 分类管理未打开时，不占用常驻列表区域；打开后仍可完成新建、重命名和删除。
- 未保存、已保存、保存失败三种状态有明确文案和视觉反馈，且不依赖右侧栏才能发现。
- Notes、Skills、AI 任务在大窗口和窄窗口下都可访问。
- 左右侧栏折叠、快捷键、Markdown 编辑行为和现有 Browser AI 流程不回归。
- 深色和浅色主题下无硬编码白/黑色造成的对比度问题。
- 新增文案全部进入 `learning` messages，不在组件中散落硬编码字符串。

## 十一、待评审问题

1. 笔记右侧信息栏是否默认展开？建议保留当前默认展开，待用户熟悉后再根据使用数据考虑默认收起。
2. 编辑区是否新增纯编辑模式？建议新增。它能减少写作时的预览干扰，同时保留分栏和预览。
3. 分类管理使用弹层还是独立对话框？建议使用轻量弹层承载常用新建，重命名/删除继续使用确认对话框。
4. AI 任务是否继续作为顶级视图？建议保留。它已经具备独立历史和详情流程，继续塞入笔记弹窗会增加上下文负担。
5. 是否需要在本轮加入可拖拽调整左右栏宽度？建议暂缓，先完成固定区间和响应式折叠；宽度拖拽会增加状态持久化和窄窗口处理复杂度。

## 十二、建议的第一轮评审重点

请优先确认以下三件事：

1. “编辑区为主舞台、分类管理按需打开”的方向是否符合学习中心定位。
2. 三种顶级视图是否继续保留，还是将 AI 任务收进浏览器 AI 入口。
3. 右侧信息栏在日常写作中是默认展开、默认收起，还是只在需要时打开。

确认这三点后，再进入 P0 实现，避免先在细节样式上投入而后续反复调整页面骨架。
