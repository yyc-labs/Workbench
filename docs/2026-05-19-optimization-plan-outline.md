# IDE Electron 优化计划大纲（2026-05-19）

## 1. 计划目标

### 1.1 总体目标
- 在不破坏现有 Runtime 工作流的前提下，提升用户操作效率、运行稳定性与可维护性。
- 优先解决高风险问题（会话管理边界、环境依赖、长会话性能退化）。
- 建立可量化的验收指标，确保优化可持续迭代。

### 1.2 本轮覆盖范围
- 用户操作
- 性能优化
- 界面友好度
- 项目识别
- 环境配置

### 1.3 不在本轮范围
- 大规模 UI 视觉重构
- 跨平台全量适配重写
- 插件系统/生态层建设

---

## 2. 优先级分层

## P0（必须优先落地，稳定性/风险）

### P0-1 会话生命周期与退出策略
- 问题：当前退出策略存在误杀非本应用 tmux 会话风险，且退出清理未显式等待完成。
- 目标：只管理应用自身会话，退出过程可控、可观测、可回退。
- 产出：
  - 会话命名与识别边界策略（前缀/标记/白名单）
  - 退出清理流程改造（限时等待 + 超时降级）
  - 会话清理日志与失败告警

### P0-2 Runtime 启动依赖治理
- 问题：Runtime 启动依赖外部固定脚本路径，环境不可移植，失败原因不透明。
- 目标：消除硬编码依赖，启动失败可诊断。
- 产出：
  - 启动脚本路径配置化
  - 启动前自检（WSL、tmux、脚本可执行性）
  - 一键诊断报告（给用户可读错误）

### P0-3 终端输出内存与解析开销控制
- 问题：终端输出长期累积，URL 扫描为全量重扫，长会话下内存和 CPU 持续上升。
- 目标：将会话资源增长控制在稳定区间。
- 产出：
  - 终端输出环形缓冲区（按字符数/行数上限）
  - URL 增量解析（仅处理新增片段）
  - 大输出压测与性能基线

## P1（高价值体验优化）

### P1-1 用户操作模型清晰化
- 问题：`Run Dev` 与 `Runtime` 操作入口混杂，删除等危险操作缺少防误触。
- 目标：让“项目运行”与“Runtime 会话”的操作心智分离。
- 产出：
  - 卡片主操作分层（Dev / Runtime）
  - 危险操作二次确认或撤销机制
  - 状态反馈统一（进行中/成功/失败）

### P1-2 启动与列表性能提升
- 问题：项目检测初始化偏串行，列表中重复环境判断与筛选计算较多。
- 目标：降低启动等待与操作卡顿。
- 产出：
  - 项目检测并发化（有并发上限）
  - 环境判定结果缓存与复用
  - 渲染性能观测点（首页首屏耗时）

### P1-3 项目识别准确率提升
- 问题：目前以文件命中为主，命令回退链不完整；路径规范化不足导致重复项目风险。
- 目标：提升识别成功率与命令可执行率。
- 产出：
  - `package.json scripts` 驱动的命令推断逻辑
  - `fallbackCommand` 实际落地
  - 路径标准化去重（Windows/WSL 统一）

---

## P2（体验打磨与工程化增强）

### P2-1 界面友好度与可访问性
- 目标：提升一致性、键盘可达性和可读性。
- 产出：
  - 焦点态/键盘导航补齐
  - 文案语言统一（中英策略明确）
  - 错误提示组件化（toast + inline）

### P2-2 可观测性与质量保障
- 目标：让回归和线上问题更容易发现与定位。
- 产出：
  - 关键链路埋点（启动、检测、会话切换、失败原因）
  - 最小自动化回归（项目识别、会话状态、配置读写）
  - CI 基础质量门禁（typecheck + lint + smoke）

## 3. 分阶段里程碑（建议）

### 里程碑 M1（1 周）
- 完成 P0-1、P0-2 设计与首版实现。
- 交付环境诊断入口与失败提示。
- 验收：不会误杀非本应用会话；启动失败可定位到具体检查项。

### 里程碑 M2（第 2 周）
- 完成 P0-3 与 P1-2。
- 验收：长时间终端会话资源占用稳定；项目多时首页加载时间显著下降。

### 里程碑 M3（第 3 周）
- 完成 P1-1、P1-3。
- 验收：用户操作路径更清晰；识别准确率和首次运行成功率提升。

### 里程碑 M4（第 4 周）
- 完成 P2-1、P2-2。
- 验收：交互一致性、可访问性与问题定位效率提升。

## 4. 验收指标（建议）

### 4.1 用户操作
- 首次添加并启动项目成功率
- 关键操作平均点击步数（启动 Runtime、打开终端、启动 Dev）
- 危险操作误触率（删除/停止）

### 4.2 性能
- 首页可交互时间（TTI）
- 50/100 项目规模下的项目加载耗时
- 长会话（30min/60min）内存增长曲线

### 4.3 识别与环境
- 项目识别准确率（按样本库）
- 命令自动推断成功率
- Runtime 启动失败率与失败类型分布

### 4.4 质量
- 回归缺陷数
- 核心链路自动化覆盖率

---

## 5. 风险与依赖

### 5.1 外部依赖风险
- WSL/tmux/外部启动脚本版本差异
- 本地开发环境权限与路径差异

### 5.2 技术风险
- 会话命名策略迁移期间的兼容性
- 输出缓冲裁剪带来的历史日志可见性下降

### 5.3 缓解策略
- 增加兼容期与迁移脚本
- 增加诊断信息与可选保守模式
- 先灰度再默认开启
