# 2026-06-26 项目全量优化修复执行计划

## 背景

本轮执行针对当前项目审查中已经确认的高优先级问题，目标不是继续补充零散建议，而是完成一轮可回归验证的全量修复。范围聚焦在以下几类问题：

1. 转录分享服务在受限环境下监听失败，导致测试不稳定且实现边界不清晰。
2. Runtime / Session 刷新链路重复触发，存在状态抖动、重复 IPC 和难维护问题。
3. 主题初始化依赖同步 IPC，preload 体积偏大，主题监听逻辑在 renderer 多处重复。
4. 主进程入口、IPC 注册和 preload 文件职责过重，继续扩展会放大维护成本。
5. 部分调试日志和平台耦合脚本影响运行时噪声与工程一致性。

## 执行目标

### P0 必须完成

1. 修复转录分享服务监听策略：
   - 区分监听地址与展示地址。
   - 优先尝试局域网绑定，失败时回退到回环地址。
   - 保持现有局域网分享能力，不以牺牲功能换测试通过。
   - 让相关测试可以稳定表达该语义。

2. 收敛 Runtime / Session 刷新模型：
   - 统一事件驱动刷新、轮询刷新、窗口激活刷新。
   - 增加 in-flight 去重与模式合并，避免重复触发。
   - 去掉依赖压制型实现，减少 `eslint-disable react-hooks/exhaustive-deps`。

3. 去除 preload 同步主题 IPC：
   - 删除 `CONFIG_GET_THEME_SYNC` 同步通道。
   - 改为 renderer 基于初始 DOM 属性与异步配置初始化主题。
   - 保留首屏主题稳定性，不引入明显闪烁。

4. 收敛重复主题监听：
   - 抽取 renderer 侧公共主题工具 / hook。
   - 统一 `TranscriptPage`、Markdown 预览、Monaco 文本查看器等逻辑。

### P1 本轮完成

1. 对主进程和 preload 做低风险拆分：
   - 把主进程启动编排拆出独立 helper。
   - 把 preload 中终端 / 运行时 / 事件订阅等收敛成可组合小块。
   - 不做大规模目录迁移，优先降低热点文件复杂度。

2. 清理明显调试日志：
   - 去掉 renderer / preload / runtime 链路中的临时 `console.log`。
   - 保留必要错误日志与边界告警。

3. 让改造后回归验证可执行：
   - 运行 `npm run typecheck`
   - 运行 `npm test`
   - 若受沙箱限制导致监听类测试无法真实起服务，需要确保代码具有明确降级语义，且测试结果可解释。

## 实施顺序

### 阶段 1：分享服务与测试稳定性

1. 扩展 `TranscriptShareService` 配置项，显式建模监听策略。
2. 为服务增加监听失败回退流程：
   - 优先使用面向局域网分享的监听地址。
   - 失败时降级到 `127.0.0.1`。
   - 更新返回的 `host` / `hosts` 结果，确保 UI 展示与真实监听一致。
3. 调整测试：
   - 不依赖单一硬编码监听方式。
   - 对主机排序与分享 URL 生成保持断言。

### 阶段 2：Runtime 刷新协调

1. 在 store 中增加统一刷新入口，接收 `sessions` / `all` 模式。
2. 实现去重机制：
   - 同一时间只允许一个刷新任务执行。
   - 后续请求合并到 pending 模式。
3. `App.tsx` 中的 Runtime 监听、轮询和焦点恢复全部改为调用统一入口。
4. 保持现有行为：
   - Runtime 启动后允许延迟补刷一次。
   - 无运行中进程时停止轮询。

### 阶段 3：主题初始化与公共监听

1. 删除同步 IPC 主题获取能力。
2. 让 `index.html` 提供稳定的默认主题标记。
3. 让 store 初始主题从 DOM 标记恢复。
4. 抽取统一的 `useEffectiveTheme` 或等价公共 hook。
5. 替换多处基于 `MutationObserver` 的重复主题监听。

### 阶段 4：主进程 / preload 轻量拆分

1. 拆出主进程启动依赖构建与窗口聚焦辅助逻辑。
2. 将 preload 中终端调用与事件订阅逻辑提取为独立模块。
3. 清理同步通道相关残留代码和未必要的内联实现。

### 阶段 5：日志与回归

1. 删除临时调试日志。
2. 保留必要错误日志与用户可见错误处理。
3. 跑完整 typecheck 和测试。
4. 根据结果补齐遗漏修复。

## 验收标准

1. 转录分享服务在监听受限环境下不再因为首选绑定失败而直接崩溃。
2. Runtime 刷新链路不再存在明显重复调用与职责分散问题。
3. renderer 启动时不再使用同步 IPC 获取主题。
4. 重复主题观察逻辑被收敛到公共实现。
5. 热点文件复杂度下降，至少完成主进程 / preload 的一轮可见拆分。
6. `npm run typecheck` 通过。
7. `npm test` 在当前环境下结果可解释，并尽量全量通过。

## 非目标

1. 本轮不重写 `TranscriptPage` 全部业务结构。
2. 本轮不引入 ESLint / CI / bash 版 AI 提交脚本的大规模工程治理改造。
3. 本轮不做 Electron 权限模型或架构级安全重构。
